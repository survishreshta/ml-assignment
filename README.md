# BeanScope ML Lab

BeanScope is an end-to-end multiclass machine-learning project for identifying dry bean varieties from geometric measurements. It includes reproducible model training, six saved classification pipelines, a held-out test dataset, and an interactive Streamlit application for live prediction and evaluation.

## Problem statement

The objective is to predict the variety of a dry bean from measurements extracted from seed images. Each observation belongs to one of seven classes:

- BARBUNYA
- BOMBAY
- CALI
- DERMASON
- HOROZ
- SEKER
- SIRA

The application accepts test observations as a CSV file, applies the selected trained model, displays predictions, and evaluates performance when ground-truth labels are available.

## Dataset description

The project uses the [Dry Bean Dataset from the UCI Machine Learning Repository](https://archive.ics.uci.edu/dataset/602/dry+bean+dataset).

| Property | Value |

The features describe bean size, shape, perimeter, axes, compactness, roundness, eccentricity, solidity, and related geometric properties.

## Data preparation

The data are divided into training and test partitions using a reproducible stratified split:

- Training data: 80%
- Test data: 20%
- Random seed: `42`
- Stratification: target class
- Test observations: 2,723

Stratification preserves the class distribution in both partitions. Standardization is included inside the pipelines for Logistic Regression, k-Nearest Neighbors, Gaussian Naive Bayes, and Support Vector Machine. Tree-based models use the original numeric scale.

## Models implemented

The following classifiers are trained on the same training partition and evaluated on the same held-out test partition:

1. Logistic Regression
2. Decision Tree
3. k-Nearest Neighbors
4. Gaussian Naive Bayes
5. Random Forest
6. Support Vector Machine

Each fitted estimator is stored as a joblib artifact. Preprocessing and classification are saved together in a pipeline wherever scaling is required, ensuring that Streamlit applies exactly the same transformations used during training.

## Evaluation methodology

The following metrics are calculated:

- **Accuracy:** proportion of correctly classified observations
- **AUC:** macro-averaged one-vs-rest multiclass area under the ROC curve
- **Precision:** macro average across all seven classes
- **Recall:** macro average across all seven classes
- **F1 score:** macro harmonic mean of precision and recall
- **MCC:** Matthews Correlation Coefficient across the multiclass predictions

Macro averaging gives each bean variety equal importance regardless of class frequency.

## Performance observations

### Logistic Regression

Logistic Regression provides a strong linear baseline. It reaches 92.14% accuracy and a high macro AUC, showing that standardized geometric features separate many bean classes effectively.

### Decision Tree

The Decision Tree produces the lowest scores among the six models. Its interpretable rules capture nonlinear relationships, but a single tree is more sensitive to training-data variation and overfitting.

### k-Nearest Neighbors

kNN performs competitively after standardization, reaching a macro F1 score of 0.9265. Its prediction cost increases with the size of the training set because it stores and searches the training observations.

### Gaussian Naive Bayes

Gaussian Naive Bayes has a strong AUC but lower hard-label accuracy. This indicates useful probability ranking, while the conditional-independence assumption limits some final class decisions.

### Random Forest

Random Forest achieves the best Accuracy, Precision, Recall, F1, and MCC. Combining 250 trees reduces the instability of a single Decision Tree and captures nonlinear feature interactions effectively.

### Support Vector Machine

The RBF Support Vector Machine achieves the highest AUC and nearly matches Random Forest on the remaining metrics. Its nonlinear decision boundaries are well suited to overlapping bean-shape measurements.

### Overall result

**Random Forest is the overall winner** because it leads five of the six evaluation metrics. Support Vector Machine is a close alternative and provides the best AUC.

## Streamlit application

The application provides:

- CSV test-data upload
- Dropdown selection across all six models
- Live predictions using the selected joblib artifact
- Prediction confidence for every observation
- Accuracy, AUC, Precision, Recall, F1, and MCC
- Confusion matrix
- Detailed classification report
- Held-out model-comparison table and chart
- Input-schema reference
- Downloadable prediction results
- Downloadable bundled test data

The uploaded CSV may include:

- All 16 feature columns plus `Class`: predictions and evaluation are displayed
- Only the 16 feature columns: predictions are displayed without evaluation

## Installation

Python 3.12 is recommended.

### Create a virtual environment

```bash
python -m venv env
```

Activate it on Windows:

```powershell
.\env\Scripts\Activate.ps1
```

Activate it on Linux or macOS:

```bash
source env/bin/activate
```

### Install dependencies

```bash
python -m pip install -r requirements.txt
```

## Run the Streamlit application

```bash
streamlit run app.py
```

Alternatively, run Streamlit directly through the environment interpreter:

```powershell
.\env\Scripts\python.exe -m streamlit run app.py
```

Open the local URL shown in the terminal, select a model, and upload `test_data.csv`.

## Reproduce model training

Ensure the source workbook exists at:

```text
DryBeanDataset/Dry_Bean_Dataset.xlsx
```

Then run:

```bash
python model/train_models.py
```

The training script will:

1. Load the workbook.
2. create the stratified train/test split.
3. Train all six classifiers.
4. Calculate the evaluation metrics.
5. Save the fitted joblib artifacts.
6. Save the label encoder.
7. Regenerate `model/metadata.json`.
8. Regenerate `test_data.csv`.

## Deployment

To deploy on Streamlit Community Cloud:

1. Push the project to a GitHub repository.
2. Ensure all joblib artifacts, `metadata.json`, `test_data.csv`, and `requirements.txt` are committed.
3. Sign in to [Streamlit Community Cloud](https://streamlit.io/cloud).
4. Create a new application from the GitHub repository.
5. Select `app.py` as the entry point.
6. Deploy and test the CSV upload with multiple models.

The deployed application loads the pre-trained artifacts and does not retrain models during startup.

## Reproducibility

- All stochastic models use `random_state=42`.
- The train/test split is stratified and reproducible.
- Every model is evaluated on the same held-out observations.
- Scaling is contained inside saved pipelines.
- Exact metric values and model-to-file mappings are stored in `model/metadata.json`.
